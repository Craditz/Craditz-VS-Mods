# Developer companion recovery

The developer panel and Recovery Ledger expose Rebuild, Rebuild all, Emergency
rebuild and Emergency rebuild all. All means the selected owner's confirmed
roster. Rebuild preserves recorded data and readable native appearance/inventory;
an incomplete record can use Emergency. Emergency uses all usable data, then
defaults missing fields. A removed animal definition or real creation/storage
failure is reported; no other species is silently substituted.

Both restore full hunger/health and clear temporary animation, movement,
away/MIA, journeys, delivery, requests, pregnancy and pending recovery state.
The rebuilt animal follows beside the operator. Known cargo and progression
remain preserved; unknown native cargo cannot be invented. Backups and retirement
of old bodies run automatically. Stale recovery history does not gate rebuilding.
Each bulk operation continues past individual failures without affecting other
owners or replaying expedition rewards. Emergency requires server admin authority.
Confirmations bind the selected owner/animal/type, expire after 60 seconds and
are single use. Internal administrative Undo/diagnostics remain available.

Rebuilding invalidates that animal's old return callbacks and missing-cart
consent. The old return journal remains in the backup and the fresh generation
starts without it. Other expedition members remain on their existing trip.

Controlled fixtures verify packet routes, resets, provenance, interruption,
save/reload and late original protection. Real provider behavior, rendered UI,
commands/animations and multiplayer save/restart remain unverified. Schema 61
requires a complete matching world/mod backup for rollback.
